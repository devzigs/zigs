      Why Zigs
      
Until now, you had to choose: shared control or privacy.

      
Teams that need approvals use a multisig and expose their treasury. Teams that need privacy use a single-key wallet and trust one person. Zigs removes the trade-off.

    

    

      
1
Shared control
Any t of n members must approve. No single person, device or server can move the funds.

      
2
Invisible on chain
No owners, no threshold, no signers, no balance. Each payment is one ordinary shielded transaction.

      
3
No custodian
Keys stay on members' devices. The relay server sees only ciphertext. The code is open source.

      How it works
      
No single person ever holds the key.

      
All cryptography runs on members' devices. The server only relays sealed messages it cannot read.

    

    
    
      
  1. Create the group
    Choose a threshold such as 2 of 3 and send the invite link. The group key travels in the link and never reaches the server.
    2. 
      
  2. Make the key together
    Devices run a three-round key ceremony. Each member keeps one share. The full spending key never exists.
    3. 
      
  3. Approve on your device
    Each approver decodes the transaction locally, sees exactly what it pays, and signs with their share.
    4. 
      
  4. Send one transaction
    Shares combine into one signature. Any member adds the proof and broadcasts. It looks like any other shielded payment.
    5.

      Security model
      
Private from the chain, and from us.

      
Every field of group data is encrypted on the device with a key that only members hold.

    

    

      

        

          
PartyCan seeCannot see

Built on standard cryptography

        

          
Re-randomized FROST, ZIP 312
Threshold signatures over RedPallas, with a fresh key per spend.

          
Zcash shielded pool
Halo2 proofs and v6 transactions. No custom chain or contracts.

          
XChaCha20-Poly1305
Each stored field is bound to its path, so the relay cannot move it.

        

        
Prototype on testnet. The code is open source and not yet audited. Do not use it with real funds.

      FAQ
      
Questions

    

    

      
Can the Zigs server move or freeze funds?
No. The server never holds a key share and cannot read group data. It can delay messages, so groups can run their own relay.

      
What happens if a member loses their device?
The group can still sign as long as enough members remain to reach the threshold. Members can back up their key share. Key refresh and member replacement are on the roadmap.

      
Is it audited?
Not yet. Zigs is a prototype on testnet. An independent audit comes before mainnet.

      
Do members see each other's payments?
Yes. Members share the group's viewing key, so each member can check the balance and every payment independently. Outsiders cannot.

      
When is mainnet?
After the audit, and once the shielded pool Zigs uses is active on mainnet.
