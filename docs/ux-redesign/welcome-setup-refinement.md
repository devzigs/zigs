# Welcome and wallet setup refinement

22 October 2026 · Web only · Baseline `cb951c4`

Applied the approved welcome/setup plan using the v3 PRD and the existing [reference mapping](art-direction.md). Tactile controls borrow the shallow raised treatment from Outcrowd; the existing porcelain/graphite palette and supplied zebra artwork remain intact. Technical reference: main `3a6c08e58fcf4a5f84016a4f68c088aea1a8195b`.

## Changes

- Top-aligned desktop zebra; full-width welcome explanations; welcome passkey action removed. Recovery and Settings locking remain available.
- Shared restrained button lighting, with unchanged 48px targets, focus indicators and disabled states.
- Compact split browser-protection layout; explicit educational browser/fingerprint/lock sequence; passkey-specific help replaces the unrelated wallet diagram.
- Visible device/approval controls, exact proposed device counts, briefly rotating example combinations and truthful invalid/all-device-risk states. Limits and acknowledgements are unchanged.
- One-wallet enclosure and live wallet/device labels update only illustration nodes. Fields, focus, selection and draft handling remain unchanged.
- Disabled Mainnet presentation; existing Testnet restriction and Solana default/opt-out/service consent remain unchanged. Compulsory Solana is [deferred](ux-ui-final-technical-review.md).

## Verification

- 128 matched captures: eight scenes at 1440×900, 1024×768, 390×844 and 320×800 in light/dark themes, plus five animation/preference captures. Chrome 155.0.8059.85 on macOS; headless browser emulation.
- 89 browser assertions cover virtual-authenticator success, cancellation and missing PRF, explicit Skip/cancel, every supported threshold pair, invalid rules, loss-warning reset, actual rotating highlights, live reduced motion, retained labels/focus/Back values, enlarged text, forced colours and preserved Mainnet/Solana controls.
- 41 Node 24 fast regression suites and the longer unified-setup suite pass. The motion suite passes 15 tests, including non-replay after live edits and immediate hidden/reduced cancellation. Strict lint and token/gradient-endpoint contrast pass; button-label contrast stays at least 4.5:1.
- Worker/web asset dry-run passes; no deployment. Test wallet rebuilt with 32 checks. Real-flow preview remains on 8792; the separate inert sample remains on 8793.
- Two 190-frame animation samples: 99.47%/100% within 20ms, p95 16.8ms, no observed long tasks or unexpected layout shifts. These local measurements do not establish physical-phone performance.
- Changed production JS/CSS adds 3442 gzip bytes using per-file gzip comparison. No dependencies or replacement artwork. PNGs contain only IHDR/IDAT/IEND chunks.

## Limits and deliberate behavior

Closed welcome fits all four tested viewport sizes; expanded welcome fits both desktop sizes. Browser protection fits 1440/1024/390 widths; the 320×800 viewport can scroll slightly. The tested 2-of-4 threshold and device screens fit at 1440×900. Expanded help, final review, larger arrangements, shorter viewports and enlarged text retain scrolling and accessible footer actions rather than clipping disclosures.

Illustrations never authorize protection, formation or payment. Normal redraws settle them immediately; initial service-metadata redraws can therefore interrupt an entrance sequence. Motion captures below use a settled setup context. Reduced motion and hidden documents cancel effects.

QR regression was skipped because qrencode is unavailable. Physical phones, Safari, real software keyboards and assistive technology remain untested. No live funded signing, new network support or recovery/security certification is claimed.
